# AgentTunnel relay protocol (v1)

How a phone reaches an `atd` daemon that has no inbound port. Shared contract
for `atrelay` (server), the daemon's outbound client, the desktop pairing UI,
and the mobile app.

## Model

```
phone ──wss──▶ atrelay ◀──wss── atd (outbound only)
```

- `atrelay` is a self-hosted binary that routes frames between **one daemon**
  and its **paired phones**. It never interprets RPC methods.
- The daemon only dials out. The relay feature is **off by default**; enabling
  it (desktop settings or `atd --relay <url>`) is the only thing that opens a
  socket. No inbound listener is added.
- Phone traffic is the existing daemon JSON-RPC (`/ws` surface in
  `internal/transport`), passed through unchanged.

## Privacy stance (decided)

The relay operator **sees plaintext** prompts, agent output, and file
contents. This is documented, not hidden: **run your own relay**. The hosted
or shared relay of someone else is trusted exactly as much as you trust them.
The relay persists no message bodies (see Relay state). Frames reserve an
optional `enc` field (below) so end-to-end encryption can be added later
without changing routing.

## Deployment (decided)

- **Public**: run `atrelay` on a host with a public name behind a TLS
  terminator (Caddy/nginx/cloudflared) → `wss://relay.example.com`. Plain `ws://`
  is accepted only when the host is loopback or an RFC1918/link-local address.
- **LAN/loopback mode**: `atrelay --listen 127.0.0.1:7777` or a LAN address,
  no TLS, for same-network use and tests.
- The mobile app accepts **any relay URL**; nothing is hardcoded.
- Endpoints: `GET /v1/daemon` (daemon socket), `GET /v1/client` (phone socket),
  `POST /v1/pair/redeem` is **not** used; pairing is a frame (below), so the
  same socket path and auth rules apply everywhere.

## Transport and framing

WebSocket, text frames, one JSON object per frame. Two layers:

**Control frames** (relay-terminated, hop-by-hop) have a `t` field:

| t | dir | purpose |
|---|---|---|
| `hello` | daemon→relay, client→relay | first frame; authenticates the socket |
| `pair` | client→relay | redeem a pairing code |
| `attach` | client→relay | bind an authenticated client to its instance |
| `ack` | relay→peer | result of hello/pair/attach |
| `ping`/`pong` | either | keepalive (30 s) |
| `bye` | relay→peer | server closing, with `reason` (`revoked`, `replaced`, `shutdown`) |

**Data frames** are JSON-RPC 2.0 objects *exactly as the daemon speaks them*
(requests, responses, `thread.event` notifications) with no `t` field. The
relay forwards them verbatim between a client and its daemon. Only routing
metadata is added by the relay on the daemon side: `"c": "<clientId>"`, a
top-level sibling of the JSON-RPC fields, so one daemon socket multiplexes
many phones. Daemon→relay frames carry `c` to target one client, or omit it
to fan out to all attached clients (used for `thread.event`).

**Reserved envelope.** Any data frame may instead be
`{"enc": {"v":1,"alg":"...","n":"...","ct":"..."}, "c": "..."}` carrying the
JSON-RPC object encrypted. v1 relays and clients must route on `c` only and
never inspect JSON-RPC fields; v1 endpoints emit plaintext and reject `enc`
frames with `ack` error `enc_unsupported`. Max frame 4 MiB.

## Authentication: never in a URL

URLs are logged by proxies. No token, code, or secret appears in a path or
query string. Auth is the **first frame** (`hello`) on the socket (browsers and
React Native can both do this); native clients may alternatively send
`Authorization: Bearer <token>` on the upgrade. A socket with no valid
`hello` within 5 s is closed. (The daemon's own `?token=` on local `/ws`
remains for loopback use only and is not used through the relay.)

### Daemon hello
```json
{"t":"hello","role":"daemon","instance":"<instanceId>","secret":"<daemonSecret>","resume":"<lastSeq>"}
```
`instance` = random 128-bit id (hex) generated by the daemon once and stored
in its StateDir. `daemonSecret` = 256-bit random, generated at first enable,
stored in StateDir; the relay stores only its SHA-256 on first sight
(trust-on-first-use per instance id) and compares in constant time. An
unknown instance with a valid shape registers; a known instance with a wrong
secret is rejected (`ack` `bad_secret`, close 4401).

### Pairing
1. Desktop asks its daemon (`relay.pair.start` RPC) → daemon sends over its
   socket `{"t":"pair-offer","code":"..."}`; relay stores the offer.
2. **Code**: 10 characters from Crockford base32 (no `ILOU`), 50 bits of
   entropy, grouped `XXXXX-XXXXX`, from a CSPRNG. Entry ignores case, spaces
   and dashes. **TTL 5 minutes**, **single use** (consumed on first
   successful redeem), at most one live code per instance (a new one
   supersedes).
3. **QR payload == manual entry.** The QR encodes the URL
   `agenttunnel://pair?relay=<wss-url>&code=<XXXXX-XXXXX>`; manual entry takes
   relay URL + code. Both decode to the same `{relay, code}` pair and feed the
   same `pair` frame. The code is not the credential and expires, so putting
   it in a QR URI is acceptable; it is never sent as a URL to the relay.
4. Phone opens `/v1/client` and sends
   `{"t":"pair","code":"XXXXX-XXXXX","name":"Pixel 9"}`.
5. Relay verifies in constant time, enforces limits, and replies
   `{"t":"ack","ok":true,"instance":"<id>","instanceName":"<label>","token":"<clientToken>","expires":"<RFC3339>","clientId":"<id>"}`.
6. **Rate limit**: 5 failed `pair` attempts per source IP per minute. Failures
   count only against that address; no live code is invalidated, so one
   address cannot lock out another instance's pairing. Failures are uniform
   (`bad_code`) whether the code is wrong, expired, or used.

**Instance binding**: a client token is bound to exactly one `instance` id.
`attach` to any other instance fails.

**Token**: 256-bit CSPRNG, base64url, opaque. Relay stores SHA-256 hash +
`{clientId, instance, name, issuedAt, expires, lastSeen}`. Lifetime 90 days,
sliding on use; revoked immediately on unpair. Compared in constant time.

### Client attach
```json
{"t":"hello","role":"client","token":"<clientToken>"}
{"t":"attach"}
```
`attach` is required after `hello`; relay answers `ack` with
`{"daemon":"online"|"offline"}` and thereafter pushes
`{"t":"status","daemon":"online"|"offline"}` on change. Data frames sent while
the daemon is offline get a JSON-RPC error `-32001 daemon_offline`.

### Unpair / revoke
Desktop `relay.unpair {clientId}` (or "unpair all") → daemon sends
`{"t":"revoke","clientId":"..."}` on its socket. The relay deletes the token,
sends `bye reason=revoked` and **closes that client's sockets**; any later
`hello` with the token fails `bad_token` (4401). A phone-initiated unpair
sends `{"t":"revoke"}` for itself. Rotating `daemonSecret` revokes everything.

## Daemon side behavior

- Outbound `wss`/`ws` only; no new `net.Listen`. Default off; setting persisted
  in StateDir settings.
- The daemon runs a virtual connection per `clientId`: a data frame with `c`
  is handed to the same dispatcher a local `/ws` client uses; replies and that
  client's `thread.subscribe` events are sent back tagged `c`. Closing a
  client (`bye`/detach) tears down its subscriptions.
- **Reconnect**: exponential backoff 1 s → 60 s with full jitter, reset after 30 s
  of health. Phones reconnect the same way and re-run `thread.subscribe` plus
  a `thread.events`/`thread.get` read (the daemon is the source of truth, so
  resume = re-read, not replay of relay-buffered bytes).
- **Bounded buffers**: per-client outbound queue 256 frames / 4 MiB; overflow
  drops the oldest `thread.event` notifications and sends the client a
  `{"t":"status","resync":true}` hint so it re-reads. Never grows unbounded.
  The relay buffers at most 64 frames per client for ≤10 s during a daemon
  reconnect blip; otherwise it returns `daemon_offline`. `hello.resume` is
  advisory (diagnostic only) in v1.
- One daemon socket per instance; a newer `hello` replaces the old
  (`bye reason=replaced`).

## Relay state

Persisted (small JSON/bolt file): instance ids, SHA-256 of daemon secrets,
client token hashes with metadata, pairing offers (memory only, never on
disk). **No message bodies are ever written**: data frames live only in
bounded in-memory queues and are not logged. Logs record connection
events and error codes, never frame contents or secrets.

## Error codes (in `ack`/close)

`bad_code`, `bad_token`, `bad_secret`, `rate_limited`, `daemon_offline`,
`enc_unsupported`, `frame_too_large`, `unsupported_version`. WebSocket close
4401 = auth failure, 4429 = rate limited.

## Test checklist for implementers

Single-use and expired code rejected; 6th bad attempt rate-limited; token
never in any URL (assert on handshake request lines); instance binding; unpair
closes live sockets and blocks reconnect; daemon opens no listener when relay
is off; overflow drops events but not RPC replies; relay persists nothing from
data frames.

## As built (v1)

The first implementation (`pkg/relay`, `internal/relay`, `cmd/atrelay`) needed
these additions. They are control frames with a `t` field and do not change
any frame above.

- **Daemon hello** may carry `name` (the label phones see; default
  `AgentTunnel`) and `v` (must be `1` when present).
- **Pairing**: the daemon mints the code (CSPRNG) and sends it as `pair-offer`.
  The relay keeps only its hash, in memory. A successful `pair` closes the
  socket after its ack; a failed one closes it with 4401, or 4429 when rate
  limited.
- **Relay → daemon**: `devices` (a snapshot of that instance's phones, sent
  after every daemon ack), `paired` and `unpaired` (live deltas), and `detach`
  (a phone's socket closed, so the daemon drops that client's subscriptions).
- **Daemon → relay**: `revoke` with `clientId`, or `all: true` for unpair-all.
  A phone revoking itself sends `{"t":"revoke"}`, and the daemon gets
  `unpaired`.
- **Extra error codes**: `bad_hello` (malformed first frame), `bad_instance`
  (attach names another instance), `not_attached` (data before attach), and
  the JSON-RPC errors `-32001 daemon_offline` and `-32002 daemon_busy`.
- **Daemon RPCs**: `relay.status`, `relay.enable {url}`, `relay.disable`,
  `relay.pair.start`, `relay.devices.list`, `relay.unpair {clientId | all}`.
  `atd --relay <url>` enables the relay the same way the desktop does, and the
  setting persists.
- **Daemon hello limits**: at most 30 hellos per source IP per minute
  (`rate_limited`), and at most 1000 registered instances by default
  (`too_many_instances`). The cap is `Options.MaxInstances`; `atrelay` has no
  flag for it yet. Known daemons still connect at the cap.
- **Behind a TLS proxy**: `atrelay -trust-proxy-header X-Forwarded-For` makes
  the per-IP limits read the last entry of that header. Off by default. Enable
  it only when your proxy sets the header itself, since otherwise clients can
  choose their own address.
- **Relayed phones cannot configure the relay**: a relayed connection refuses
  every `relay.*` RPC with `-32003`. Only the desktop app can pair or unpair.
- **Secrets on disk**: the daemon keeps its instance id, secret, and device
  list in `<stateDir>/relay.json` (mode 0600). The relay keeps only hashes.

Not built in v1. These are deliberate cuts, and the spec above still describes
the intent:

- No 64-frame, 10 s relay buffer during a daemon reconnect. A phone whose
  daemon is offline gets `daemon_offline` at once and re-reads after it
  reconnects.
- Keepalive pings run both ways every 30 s, but no liveness timeout is
  enforced. TCP and the proxy decide when an idle socket dies.
- Bounded outbound queues are per daemon socket, shared by its sessions, not
  per client. Overflow drops the oldest `thread.event` and leaves one resync
  hint per affected client. RPC replies are never dropped. On the relay, a
  phone whose 256-frame queue overflows is disconnected.
- `Authorization: Bearer` on the upgrade is not accepted. The first-frame
  `hello` is the only client auth path.
- `hello.resume` is ignored. `daemonSecret` rotation is not implemented.
